# Threat model

Scope: Synaptome 0.2.0 as built by `npm run build` and run on one person's machine. Assets: the person's AI hosts
(their skill, agent, command and MCP configuration), their projects, their credentials (GitHub, model providers), the
Synaptome data folder, and the person's attention (what a host is told to do). Trust boundaries: content from discovery
sources (hostile until shown otherwise), AI hosts (trusted to follow their documentation), the local browser (other
sites in it are hostile), other local processes (not trusted with the dashboard), and the person (trusted).

Status words: **Mitigated** (a control exists and a test proves it), **Fixed in Phase 11** (found in this review, fixed,
tested), **Accepted** (residual risk accepted in writing, with the reason), **Open** (not yet addressed; release impact
stated). Control details: `docs/SECURITY_MODEL.md`.

| ID | Threat | Controls | Tests | Status |
|---|---|---|---|---|
| T-01 | **Malicious capability content** (skill text, scripts, manifests) executes or spreads | Never executed by Synaptome; quarantine under `<home>/quarantine` with path normalisation; static audit (injection, concealment, exfiltration, pipe-to-shell, reverse shells, packed code, hidden Unicode); tiers (C never leaves quarantine); gate with 15 evidence-backed checks, unknown counts as failing; executable content always needs a person because no isolation provider exists (dynamic tests BLOCKED, D-020) | `corpus.test.ts` (26/26 malicious blocked, 0/15 benign), `policy.test.ts`, `acquisition.test.ts` | Mitigated; residual: a person may approve executable content without a dynamic test — the gate says so in its evidence (Accepted) |
| T-02 | **Prompt injection** through capability text served to a host model | Hosts get short summaries labelled as reference material beneath the user's instructions; full text only when the host asks for one approved capability; blocked/unapproved never offered; budgets fixed by settings, not content; audit flags injection phrasing | `v2.test.ts`, routing benchmark, `corpus.test.ts` | Mitigated; residual: approved text can still persuade a model (Accepted: same as any skill a person installs; approval is the control) |
| T-03 | **MCP tool poisoning** (tool descriptions that instruct the model) | Audit rules for tool-description injection; MCP servers written only into a named project's `.mcp.json`, never user scope; Synaptome never starts MCP servers; secrets only as `${VARIABLE}` references | `corpus.test.ts`, `adapter-kinds.test.ts` | Mitigated |
| T-04 | **Supply chain of capabilities** (moved tags, changed publishers, swapped content) | Pinned commit/version; content hash per snapshot, re-hashed on every read; publisher-change detection; update inspection flags licence, permission, executable and publisher changes; updates never applied automatically | `core.test.ts`, `install-matrix.test.ts`, `supply.test.ts` | Mitigated; Open: no signature verification of upstream releases, no advisory database for capability dependencies (release impact: documented limitation) |
| T-05 | **Supply chain of Synaptome itself** (its own npm dependencies) | One package with no runtime dependencies (all bundled at build time, D-028); `build-info.json` lists every bundled package; licence inventory (`scripts/licenses.ts`); `npm audit` in the release checks | `build.test.ts` | Mitigated for licences; vulnerability scan results in `docs/SECURITY_REVIEW.md` |
| T-06 | **Unsafe shell use** | Workflow `shell` steps off by default, allow-listed programs, `shell: false`; fixed command lines for `bridge verify` and scheduler registration (task text on stdin); this review found two places where values reached `cmd.exe`: the configured model name and program path of the headless Claude Code provider, and the npm fallback of `upgrade` — both now refuse shell syntax | `providers.test.ts` (refusal), `engine.test.ts` (shell steps off by default, allow-listed, no shell) | Fixed in Phase 11; Open: the provider still starts `claude` through `cmd.exe` on Windows (Node refuses `.cmd` files without a shell); arguments are built internally and quoted |
| T-07 | **File system reach** beyond what the person chose | Writes only to the data folder, sandbox hosts, a named project, or a real host folder after `--real --yes` with a verified staged install and a budget; never overwrites content it did not create; per-location lock; edits never discarded silently; `uninstall --everything` undoes only recorded changes | `install-matrix.test.ts`, `adapter-kinds.test.ts`, `setup.test.ts` | Mitigated |
| T-08 | **Network reach** | Requests only to discovery sources within their terms (robots.txt), backoff and daily budgets; model providers only when a command says so and the privacy setting allows; the dashboard listens on loopback only | `sources.test.ts`, `providers.test.ts`, `service.test.ts` | Mitigated |
| T-09 | **Credential exposure** | GitHub and provider credentials read from the environment (or `gh`) at request time, never stored or logged; dashboard token per start, sent in a header, never in a URL (D-010); packed package scanned for token-shaped strings | `service.test.ts` (no `?token=` accepted), `build.test.ts` (secret scan) | Mitigated; history scan in `docs/SECURITY_REVIEW.md` |
| T-10 | **Hooks** run on every prompt in a connected project | Only in the project's local settings, never global; prints nothing for small or administrative prompts; hard token budget; never serves blocked or unapproved capabilities; Synaptome's own model calls carry a flag the hook obeys (no self-routing) | `bridge.test.ts`, `v2.test.ts` | Mitigated |
| T-11 | **Privilege escalation** by a capability (asking for more permissions over time, or a forged skill granting itself some) | Permission analysis per version; update inspection flags new permissions; gate check "no permission escalation"; forged skills cannot declare new permissions; policy rules can only tighten the gate | `policy.test.ts`, `maturity.test.ts` | Mitigated |
| T-12 | **Unsafe updates** of Synaptome itself | `upgrade` keeps the running version and a database copy, the new version must pass `doctor` or both are put back; rollback never silently replaces newer data; an older version refuses a newer database | `upgrade.test.ts` | Mitigated; Open: the npm package is not yet signed/provenance-attested (Phase 12, needs publishing) |
| T-13 | **Local HTTP API abuse** by other sites in the browser or other local users | Loopback bind; per-start random token in a custom header (a cross-site page cannot set it without a CORS preflight, which is never allowed); Origin and `sec-fetch-site` checks; CSP with `frame-ancestors 'none'`; every one of the 62 commands refuses a missing token, a foreign origin and a foreign Host | `service.test.ts` | Mitigated; Accepted: another process running as the same user can read the token from the page it fetches (same-user processes are inside the trust boundary on a single-user machine) |
| T-14 | **DNS rebinding** | Host header allow-list (127.0.0.1, localhost with the bound port); foreign Host refused on every route | `service.test.ts` | Mitigated |
| T-15 | **Database integrity** | WAL with busy timeout; transactions for multi-row changes; `integrity_check` in `doctor` and `repair` (reported, never "fixed" by rewriting); copy before every migration and upgrade; migration of a legacy home is copy-only with verification | `core.test.ts`, `migrate.test.ts`, `setup.test.ts` | Mitigated |
| T-16 | **Concurrent writers** (CLI, TUI, dashboard, MCP server, scheduler at once) | Host-location locks with stale-lock takeover; unique index on live installations; SQLite WAL; events read only once committed | `install-matrix.test.ts` (two cross-process races), `watch.test.ts`, `stress.test.ts` | Mitigated |
| T-17 | **Malformed input** to parsers (front matter, manifests, API arguments) | Input validation at the API boundary; parsers bounded by size; fuzzing of the front-matter parser, the dependency parsers and the HTTP API | `fuzz.test.ts` | Mitigated (see `docs/SECURITY_REVIEW.md` for the runs) |

## Findings of this review and what happened to them

| Finding | Where | Resolution |
|---|---|---|
| Configured model name and program path reached `cmd.exe` unquoted | `packages/evaluation/src/index.ts` (headless Claude Code) | Fixed: refused unless they match a strict pattern; test added |
| `upgrade` npm fallback passed the user's spec through a shell | `apps/cli/src/commands/upgrade.ts` | Fixed: refused when it contains shell syntax |
| `SECURITY_MODEL.md` described the event stream as cookie-authenticated | docs | Fixed: it is a header-authenticated fetch stream (D-010) |
| A rate-limited scan was reported as completed | `packages/discovery` | Fixed in Phase 10 (partial status with the reason) |
| A refused database open left the file locked | `packages/core/src/db.ts` | Fixed in Phase 10 |
